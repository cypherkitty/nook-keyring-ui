# UX guidance for Nook

For changes to the interface, copy, or artwork, follow the [product model and setup states](README.md).

- **Open inside the password manager.** The first visit is the empty state of **My keyring**. Earlier landing-page and dashboard layouts separated setup from the vault. Show the password list as soon as the vault exists, keep it usable throughout linking, and reopen it on return.
- **Explain the destination before the first input.** Identify Nook as a local-first password manager. Let a newcomer trace **This device ↔ Your cloud account ↔ Second device** and see which copies work offline. Keep **Create vault** immediately in reach for someone who already knows the product. [GOV.UK Design System — Start using a service](https://design-system.service.gov.uk/patterns/start-using-a-service/)
- **Let the objects carry the explanation.** Use familiar device and cloud icons, two-way arrows, and short labels such as “Saved offline” and “Encrypted sync copy.” Use the provider-neutral “Your cloud account” to make ownership explicit. Reserve extra copy for instructions such as which account to use on the second device. [Nielsen Norman Group — Match Between the System and the Real World](https://www.nngroup.com/articles/match-system-real-world/)
- **Keep progress at the top.** Show all three locations together with the two-step counter. Use a filled green bar and check for saved copies, an orange marker for the current action, and a striped track for waiting locations. Inspecting a tab only changes the detail panel. On success, fill that location’s bar, attach its tag, and move focus to the next action or result. [Nielsen Norman Group — Visibility of System Status](https://www.nngroup.com/articles/visibility-system-status/)
- **Keep the keyring and its controls together.** Use the original photorealistic steel ring and orange acrylic tag beside the selected location’s action or saved details. Its assembly shows what the person has configured. Use dark graphite surfaces, square corners, and aligned fields and buttons. [Original keyring artwork](public/keyring/keyring-original.png)

On a phone and desktop, review the first visit and each saved state. In particular, connecting storage should fill the cloud bar while the count stays at **one device**. Confirm that keyboard users can inspect any location, that screen readers announce progress, and that each state is recognizable with reduced motion.
